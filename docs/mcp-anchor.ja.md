# Remote MCP アンカー検索バンドル

2026-06-04 以降、ホスト型 Remote MCP エンドポイント
`https://tlr.dr-legal.com.tw/mcp` の `search_judgments` はアンカー式レスポンスを
使用しています。

本書はホスト型 MCP ツール面に適用されます。オープンソース CLI は retrieval-only の
まま、TLR をリモート検索エンドポイントとして利用します。

## 変更点

Remote MCP フローの `search_judgments` はアンカーバンドルを返すようになりました。
サーバーは最も関連する判決の理由抜粋を先に読み込み、以下を返します：

- `allowed_citations`：authority として引用できる citation ID。
- `judgments`：理由抜粋が実際に本レスポンスに含まれた判決。
- `unread_candidates`：理由がバンドルに読み込まれなかった候補 — 原因は payload
  上限、全文の取得不能・空、あるいは（`search_bundle` の場合）`read_top` 外。
  各候補には `reason` が付き、authority として引用してはなりません。
- `verification_instructions`：下流 AI に `allowed_citations` のみの引用を
  義務付けるルール。

裁判所の論理として引用してよいのは `allowed_citations` に列挙された判決だけです。

## なぜ

従来のリスティングのみのフローでは、下流 AI が実在する台湾の事件番号を引用しつつ、
その事件に紐づく法的命題を捏造・誤帰属することが容易でした。アンカーバンドルは
タイトルだけでなく読み込んだ抜粋を AI に与えることで、この「タイトルのみ誤引用」の
リスクを低減します。

サーバーは依然として LLM を呼び出しません。検索とパッケージングのみを行います。
回答はすべて利用者自身の AI ツールが生成します。

## 重要な制限

下流 AI の忠実性を保証するものではありません。検索後の Claude、ChatGPT、Gemini、
ローカルモデルを TLR は制御できません。アンカーバンドルはタイトルのみ誤引用の
リスクを下げますが、利用者は引用判決を自分で確認すべきです。

`unread_candidates` は authority ではありません。検索メタデータとして付属するだけ
で、裁判所の論理として引用してはなりません。

## CLI バンドルおよびホスト型 `search_bundle` との関係

CLI の `pack` コマンドは、判決と引用ルールを利用者の AI ツール向けにパッケージ
します。CLI はローカルでバンドルを組み立て、返された全判決を読み込むため、
`allowed_citations` は常に同梱抜粋と一致します。

ホスト型 Remote MCP は両ツールに同じ read-whitelist の考え方を適用します：

- `search_judgments`（アンカー）：サーバーは payload 上限内で最関連の抜粋を
  読み込み、`allowed_citations` には抜粋が実際に含まれた判決のみが入ります。
- `search_bundle`（ホスト型 `/v1/pack`）：`read_top < max_results` の場合、上位
  `read_top` 件のみ全文読み込みされます。2026-06-26 以降、`allowed_citations` には
  読み込み済み判決**のみ**が入ります。残りの結果は閲覧用に `judgments` に残るものの
  `unread_candidates` に移され、authority として引用できません。（従来は未読の
  結果が空シェルとして `allowed_citations` に誤って列挙されていました — 修正済み。）

3 つのインターフェースすべてでルールは同一です：`allowed_citations` のみを引用し、
`unread_candidates` は検索メタデータとして扱い、authority としないこと。

## v1.1：`case_history` と見解レイヤーのセルフチェック

- 全文読み込み済みの判決（`fulltext_available=true`）には `case_history` が付属
  します：データベースに記録された上級審・下級審（`upper` / `lower`、各項目に
  `citation_text`、`doc_type`、`jdate`、`main_flag`）。`main_flag` が
  主文に「廢棄」（破棄）を含む旨を示す場合、その判決は上級審に破棄されており、
  現行有効な判示として引用してはなりません。上級審の記録がないことは
  データベース未収録を意味するだけで、判決の確定を意味しません。
- `verification_instructions.rules` に OPINION-LAYER SELF-CHECK が追加：下流
  モデルは回答後に、各判示の出所、裁判結果の方向（勝訴／敗訴／破棄／棄却／
  差戻し）、`case_history` の破棄フラグを一つずつ確認しなければなりません。
- クエリが完全な事件番号の場合、`search_judgments` は自動的に正確検索へ切り替わり
  ます。見つからない場合、`note` フィールドに「見つからない＝存在しない、では
  ない。推測してはならない」と明示されます。

## 2026-07-26：重複クエリの指針と期限切れトークンの復旧

ホスト型 MCP 面におけるクライアント向け挙動の更新 2 点：

- **ツール説明がバンドル再利用を指示するようになりました。**`search_bundle` と
  `search_judgments` はクライアントに対し、同じ質問を会話の中で既に検索済みなら、
  同一クエリを繰り返さずその結果を再利用するよう伝えます。同一クエリは同一判決を
  返し、重複バンドルの積み重ねは回答品質を劣化させます。
- **期限切れ `result_token` エラーが行動可能になりました。**期限切れまたは不一致の
  `result_token` を伴う `get_judgment_fulltext` は HTTP 400
  `result_token_invalid_or_expired` を返し、検索を一度だけやり直して新しい
  トークンを取得するようヒントを添えます。（文書が存在しない場合の HTTP 404 は
  従来どおり。）

## 2026-08-04：`get_legal_reference` — 行政解釈（函釈）の文書番号による正確検索（hosted MCP）

ホスト型 MCP に 4 つ目のツール `get_legal_reference` が追加されました（REST
`POST /v1/legal_reference` としても利用可能）。台湾の行政機関による解釈通達
（行政函釋／令函）を**発文番号で正確に検索**し、全文と**効力ステータス欄**を
返します。オープンソース CLI はまだこのツールに未対応です。この面の他の機能と
同様、**LLM は一切呼び出しません**。

### 用途

解釈を引用する前の存在・効力の検証：書面や法的分析で「台財稅第○○號函」を引用
する際、まずその解釈がコーパスに存在するか、データベースに廃止・適用停止の記録が
ないかを確認できます。

### 入力

- `serial`（必須）：発文番号。例：`台財稅第881945861號`、
  `(79)台勞保二字第17914號`。サーバー側で自動正規化されます：全角・半角、臺／台、
  「字第」と「第」、末尾の「函／令／公告」、漢数字（第○六八五四號）、年度接頭辞
  （（79））などの表記ゆれはすべて収束します — 事前の整形は不要です。
- `authority`（任意）：発出機関名のヒント。同一番号が複数機関に一致した場合の
  並べ替えにのみ使われ、フィルタにはなりません。

裁判の事件番号（「年度」を含む。例：`112年度台上字第9號`）は拒否され、
`search_judgments` の使用を促すヒントが返されます — 解釈と判決は別種の文書であり、
決して混在しません。

### 出力

`matches[]` の各項目には `authority`、`serial_no`（正規化後）、`title`、
`issue_date`、`fulltext`、`source_url`、および効力ステータス欄が含まれます：

| `status` | 意味 | 呼び出し側の対応 |
|---|---|---|
| `active_verified` | データベースで現行有効と検証済み | 引用可（原文の確認は引き続き推奨） |
| `unknown` | **効力未検証** | 失効を意味せず、有効の確認も意味しない。依拠する前に発出機関の法令データベースで確認 |
| `repealed` / `ceased` | 廃止／適用停止と記録 | 現行法源として引用しない |
| `superseded` | 後の通達により代替 | `superseded_by` の番号を代わりに照会 |

`status` が `unknown` の場合、レスポンスには明示的な警告が付きます — 隠すことも、
有効と装うこともありません。統合・改正型の通達は 1 レコードで複数の番号を
カバーすることがあり、そのいずれの番号で照会してもヒットします。

### 「見つからない」の意味（重要）

見つからない場合、収録範囲の説明（収録機関数と件数）が返されます。
**見つからない＝その解釈が存在しない、ではありません** — コーパスは網羅的では
なく、ヒットしないことを根拠に番号の誤りや解釈の捏造と断定してはなりません。
見つからなかった番号は、コーパス拡充の優先度に反映されます（利用実績駆動の
カバレッジ）。

### 制限

- 効力ステータスは**データベースの記録**であり、法的意見ではありません。引用前に
  発出機関の公式公告で確認してください。
- 返されるのは行政機関の解釈通達・命令資料であり、**裁判所の判決ではありません**。
  裁判所の見解として引用してはなりません。各レスポンスにこの注意が付属します。
- 解釈のトピック／キーワード探索には `search_legal_references`（下節）を
  使用してください。本ツールはこのペアのうち、正確検証と効力確認を担う側です。

## 2026-08-08：`search_legal_references` — 行政解釈のセマンティック検索（hosted MCP）

hosted MCP に 5 つ目のツール `search_legal_references`（REST
`POST /v1/legal_references/search` も提供）が追加されました。台湾の行政解釈
（函釈／令函）、行政命令、税務解釈、憲法解釈／憲法法廷裁判を**自然言語**で
検索します。本インターフェースの他のツールと同様に**LLM を一切呼びません**。
そして**意図的に関連性判断を行いません**：セマンティック類似候補を返すだけで、
判断は呼び出し側モデルに委ねます。

### 入力

- `query`（必須）：自然言語のトピッククエリ。
- `authority`（任意）：機関名の完全一致フィルタ（例：財政部）。
  `get_legal_reference` のヒントと異なり、こちらは**フィルタとして機能**します。
- `source_kind`（任意）：`administrative_interpretation` /
  `administrative_order` / `tax_interpretation` /
  `constitutional_interpretation` / `constitutional_judgment` のいずれか。
- `max_results`（任意、1–10、デフォルト 5）。

裁判所の事件番号は拒否され、`search_judgments` の使用を促します
（`get_legal_reference` と同様）。

### 出力

`results[]` の各エントリには `citation`、`serial_no`、`authority`、`title`、
`issue_date`、`source_kind`、`get_legal_reference` と同じ効力 `status`、
類似度 `score`、抜粋 `excerpt` が含まれます。サーバー側の決定論的整合性
チェックを通らなかった候補（データベース上で廃止／適用停止と記録されている
ものを含む）は除外され、**`rejected` に計上**されます。除外は必ず開示され、
silent には行われません。

### 呼び出し側検証契約（本ツールの核心）

返されるのは**セマンティック類似候補であり、検証済みの回答ではありません**。
スコアが高くても、質問との関連性・現行効力・権威性を意味しません。候補を
引用する前に、呼び出し側モデルは：

1. 抜粋を読み、関連性を自ら判断する；
2. 候補の `serial_no` で `get_legal_reference` を呼び、全文と効力ステータスを
   取得する（`repealed`／`ceased` は現行法として引用不可、`unknown` は効力
   未検証）；
3. 取得した全文に逐語的に存在するテキストのみ引用する。

2 つのツールはペア設計です：`search_legal_references` が実在する文書番号を
見つけ（モデルが記憶から番号を推測する必要をなくし）、`get_legal_reference`
が存在・原文・効力を検証します。

### 制限

- 結果が空でも、関連する解釈が**存在しないことを意味しません**。コーパスは
  網羅的ではなく、セマンティック検索は列挙ではありません。
- 返されるのは行政機関の資料であり、**裁判所の判決ではありません**。裁判所の
  見解として引用せず、判決の引用と混在させないでください。各レスポンスに
  この注意が付属します。
- 解釈と判決は厳格に分離されたままです。本ツールが判決を返すことはなく、
  判決ツールが解釈を返すこともありません。


## 2026-08-20 更新（search_bundle / get_judgment_fulltext）

- `search_bundle` レスポンスに `result_token` を追加（`unread_candidates` を含む
  bundle 内の任意の doc_id を `get_judgment_fulltext` で読取可能）。
  read-whitelist の規律は不変。
- `judgments[]` に `hit_excerpt`（ヒット箇所プレビュー）を追加。引用は理由全文で。
- `get_judgment_fulltext` に `excerpt_offset` / `fulltext_total_chars` を追加。
  `fulltext_truncated=true` の間はオフセットでページング。
- 語彙モード（`keyword` / `phrase`）は関連度順・ゼロヒット時空返却に。

## 2026-09-01：`get_law_article` — 現行法条の完全一致照会（hosted MCP）

hosted MCP に 6 つ目のツール `get_law_article` を追加（REST
`POST /v1/law_article` でも利用可）。**法令名＋条番号**で現行条文を照会します。
本サーフェスの他のツールと同様、**LLM を一切呼びません**。法令コーパスは
全國法規資料庫（台湾の公式法令データベース）のミラーで、定期同期されます。

### 用途

法条引用前の検証：条番号の実在、現行条文の逐語内容、法令の廃止注記の有無。
改正で条番号はずれ、モデルの記憶から再現された条文はもっともらしい幻覚で
あることが多いため、記憶を照会に置き換えます。

### 入力

- `law_name`（必須）：公式名または慣用略称（勞基法、刑法、憲法など）。
- `article_no`（必須）：`184`、`第184條`、`47-1`、`第47條之1`、漢数字
  （第十八條）を受理。

### 出力

`matches[]` 各件に公式 `law_name`、`law_level`、`law_modified_date`
（最終改正日）、`law_url`（公式データベースへのリンク）、`abolished`
（廃止注記フラグ）、正規化済み `article_no`、`article_content`（当該条の
現行全文）。条文の引用は **必ず** `article_content` から逐語で。

### 該当なしの意味

- 法令は解決したが条番号が見つからない場合：明示的にその旨を返します。
  コーパスは法令を丸ごと収録しているため、通常は条番号の誤りか改正による
  繰り上げ・繰り下げを意味します。
- 法令名が解決しない場合：`law_candidates` に類似名を列挙します。該当なしは
  法令の不存在を証明しません（自治条例や一部の行政規則は収録範囲外）。

### 制限

- **現行整備版のみ**。改正前（行為時法）の条文検証には使えません。沿革は
  `law_url` から公式データベースで確認してください。
- 法令のみ：行政解釈は `get_legal_reference`、裁判は `search_judgments` へ。
