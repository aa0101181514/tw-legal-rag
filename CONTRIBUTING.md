# Contributing

## TL;DR — issues welcome, pull requests are not accepted

This project keeps a **single-author codebase**: every line is written and
owned by the project author. This is a deliberate licensing decision, not a
statement about code quality — it keeps the copyright unambiguous so the
project can offer clear commercial licensing and change terms without
tracking down past contributors.

What this means in practice:

- **Bug reports and feature requests: yes, please.** Open an issue and
  describe the problem, steps to reproduce, and expected behaviour. Several
  shipped fixes started as community issue reports, and they are credited in
  the changelog.
- **Pull requests: politely declined.** PRs will be closed with a pointer to
  this document, regardless of quality. If the underlying problem is real,
  it will be re-implemented first-party and the issue credited.
- **Please do not paste patches or code into issues.** Describe the problem
  instead. Code pasted into an issue cannot be merged for the same licensing
  reason, and it makes an independent fix harder to write cleanly.

Precedents for this model: SQLite and Litestream, among others, follow the
same policy for the same reason.

Forking is fine within the license terms (see `LICENSE`; versions ≤ 1.2.2
remain MIT). The project name is not licensed — see `TRADEMARK.md`.

# 貢獻指南（繁體中文）

## 重點：歡迎開 issue，但不接受 pull request

本專案刻意維持**單一作者的程式碼庫**：每一行都由專案作者撰寫並持有著作權。
這是授權策略的決定，與程式碼品質無關。目的是讓著作權歸屬單純，
專案才能提供明確的商業授權，未來調整條款也不需要逐一取得歷任貢獻者同意。

實務上的意義：

- **回報 bug、提功能需求：非常歡迎。** 請開 issue 描述問題、重現步驟與
  預期行為。過去多個修正都源自社群回報，changelog 都有列名致謝。
- **Pull request：一律婉拒。** 不論品質，PR 都會附上本文件連結後關閉。
  問題若屬實，會由專案方重新實作，並在 issue 致謝。
- **請不要在 issue 裡貼程式碼或 patch。** 請改為描述問題本身。
  基於同樣的授權理由，貼在 issue 的程式碼無法被採用，
  反而會讓乾淨的獨立實作變得困難。

同樣採取此模式的先例：SQLite、Litestream 等。

在授權條款範圍內 fork 沒有問題（見 `LICENSE`；1.2.2 以前的版本維持 MIT）。
專案名稱不在授權範圍內，詳見 `TRADEMARK.md`。
