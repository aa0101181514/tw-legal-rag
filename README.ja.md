> 法律偵探（Legal Detective）が構築した 2,200 万件の判決検索基盤に接続する、
> 台湾判決の**セマンティック検索**オープンソース CLI。

Taiwan Legal RAG CLI は、法律偵探の公開 TLR エンドポイントから台湾の裁判所判決を
検索し、**あなた自身の AI ツール**で使える形にパッケージするツールです。本ツールは
法的助言を**生成せず**、いかなる LLM も**呼び出さず**、第三者モデルの出力の意味的
忠実性を**保証しません**。内蔵の引用チェックは、引用された判決が取得済みバンドルに
含まれるかどうかのみを検証します。

## 何が違うのか

これは一般的なキーワード型の判決検索ツールではありません。背後にあるのは法律偵探が
長期にわたり構築してきた TLR 検索サービスです：

- 約 **2,200 万件**の台湾裁判データを構造化処理・ベクトル化。
- 数千時間におよぶ検索パイプラインの最適化。
- **セマンティックあいまい検索**対応 — 事件番号・裁判所名・キーワードに頼らず、
  自然言語で「概念は近いが用語が異なる」判決を探せます。
- **事件番号による正確な取寄せ**（v1.1）— クエリが完全な裁判文書番号
  （例：最高法院112年度台上字第9號）の場合、自動的に正確検索に切り替わり、
  その事件番号のデータベース内文書を返します（同一番号の民事・刑事事件は並記して
  ラベル表示）。**見つからない場合は明示的に告知します**：「見つからないことは
  その裁判が存在しないことを意味しない。事件内容を推測してはならない」。意味的に
  近い結果で水増しすることはありません。
- **審級関係 `case_history`**（v1.1）— 判決全文を読む際、データベースに記録された
  上級審・下級審の情報が付属します（主文に「廢棄」（破棄）を含む旨のフラグを含む）。
  **引用する前に、その判決が上級審に破棄されていないかを確認できます。**
  上級審の記録がないことはデータベース未収録を意味するだけで、判決の確定を
  意味しません。
- **行政解釈（函釈）の文書番号による正確検索 `get_legal_reference`**
  （2026-08、hosted MCP）— 発文番号（例：台財稅第881945861號）で行政解釈の全文と
  **効力ステータス**（検証済み有効／未検証／廃止／適用停止／後令により代替）を
  照会できます。解釈を引用する前に存在と効力を検証してください。見つからない場合は
  **「見つからない＝存在しない、ではない」**ことを明示します。行政解釈と判決は
  厳格に分離され、同一ランキングに混在せず、裁判所の見解として引用してはなりません。
  詳細は [`docs/mcp-anchor.md`](docs/mcp-anchor.ja.md)。
- **引用保護は後付けではなく第一級の設計要素** — 各バンドルには
  `allowed_citations` ホワイトリスト（理由全文を実際に読み込んだ判決のみ）、
  `unread_candidates` マーク（理由未読の判決は authority として引用不可）、
  すべてのバンドルに書き込まれる検証指示（見解レイヤーのセルフチェックを含む）、
  さらに CLI 側のバンドルレベル引用チェックが付属します。この設計全体が、
  リーガル AI で最も深刻なハルシネーション型 —— **事件番号は実在、判示は捏造** ——
  を標的にしています。一般的な検索ツールはデータをモデルに渡して終わりですが、
  ここでは「引用規律」をデータ形式そのものに組み込んでいます。
- オープンソース CLI 自体は**判決データベースを内蔵せず**、バックエンドの
  モデル重みやベクトルインデックスも公開しません。公開 TLR 検索エンドポイントに
  接続するクライアントです。

### 「公式サイトラッパー」型ツールとの違い

もう一つの一般的な手法は、司法院・法令の公式サイト内検索へリアルタイムに
転送するものです。両者は役割が異なり、補完関係にあります：

| | 公式サイトラッパー | Taiwan Legal RAG |
|---|---|---|
| 検索方式 | 公式サイト内キーワード検索 | 自前構築の 2,200 万件コーパスに対するセマンティック検索。概念が近ければ用語が違っても見つかる |
| 引用保護 | 通常なし | read-whitelist + 検証指示 + 引用チェック |
| 事件番号取寄せ | サイトの機能に依存 | 正確検索。見つからない場合は「推測禁止」を明示 |
| 審級関係 | 事件ごとに自分で追跡 | `case_history` が自動付属、破棄フラグ付き |
| 可用性 | サイトの WAF・改版の影響を受け、ローカルブラウザで認証回避が必要なことも | ホスト型エンドポイント、ローカル環境不要 |
| 即時性 | 公式サイトはリアルタイム | ごく最近公告された裁判は公式サイトを優先 |

ラッパー型の強みは即時性と公式ソース直結、本ツールの強みはセマンティック検索の
品質と引用規律です。

（補足：オープンソースなのは **CLI** であり、モデルやベクトルストアでは
ありません。バックエンドの検索サービス・モデル重み・非公開インデックスは
サーバー側に留まり、本ツールと共に公開されることはありません。）

## できること／できないこと

**できること**：自然言語で判決を検索 → 構造化リスト・判決理由の抜粋・引用リンクを
取得 → バンドルにまとめて自分の AI に渡す。AI が生成した回答に対する
バンドルレベルの引用チェック。

**できないこと**：本ツールは **LLM を呼び出さず、法的意見を生成せず、いかなる
モデル出力も保証しません**。回答はあなたが選んだ AI（ChatGPT / Claude / Gemini /
ローカルモデル）が生成します。

### 内蔵の引用チェックで検証できること

`check` は**バンドルレベルのベストエフォート**文字列チェックで、以下のみを
検証します：

- 回答が引用した判決番号が**バンドル内にあるか**（「バンドル外の番号を引用」＝
  捏造の疑いを検出）；
- バンドル外あるいは実在しない判決の引用；
- **引用文の存在（バンドルレベル）**：回答が「裁判所いわく……」とする逐語文が、
  バンドルテキストの**どこか**に存在するか。

### 検証**できない**こと（重要）

- 引用文が**回答の指すその判決**に由来するか（存在チェックは「バンドル全体の
  どこかにあるか」のみを見て、特定判決に紐付けません）；
- 裁判所の判示を**正しく読めているか**；
- **当事者の主張**（原告・被告・上訴人）を**裁判所の見解**と取り違えていないか；
- **傍論**を判決の**中核的権威**として扱っていないか；
- 言い換え（パラフレーズ）型の判示ハルシネーション。

これらはいずれも判決全文を読まなければ判断できません — だからこそバンドルには
判決抜粋と検証指示が同梱され、下流モデル自身に照合を義務付けています。
**`pass` は「引用番号の同一性がバンドルと一致した」ことだけを意味し、「法的推論が
正しい」「引用文が確かにその判決に由来する」ことを意味しません。** また `check` は
**バンドル内のコンテンツ**とのみ比較します。法律偵探のデータベース全体では
ありません — 後で自分で判決全文を開いて回答を書き直しても、`check` が見るのは
当初パックされた抜粋だけです。

## インストール

```bash
pip install twlegalrag
```

依存は `httpx` / `typer` / `rich` のみ。LLM パッケージも API キーも不要です —
本ツールは LLM を呼び出しません。

## 使い方

```bash
# 1) 検索のみ — 該当判決をリスト表示
twlegalrag search "勞資 加班費" -n 5 --read

# 2) パック — 任意の AI に渡せるバンドルを生成 ★メインフロー
twlegalrag pack "車禍對方全責,我可以求償什麼?" -o bundle.json
#   → bundle.json を ChatGPT / Claude / Gemini に貼り付け、バンドル内の判決のみ
#     引用するよう指示する

# 3) 引用チェック — AI が生成した回答へのバンドルレベル検査
twlegalrag check bundle.json answer.txt

# サービス稼働確認
twlegalrag health
```

`pack` が生成するバンドルには `query`、各判決の `citation_id`（J1, J2, ...）、
`citation_text`、`citation_url`、`doc_id`、Layer-1 リスト、`fulltext_excerpt`
（判決理由の抜粋、長さ上限あり）、`case_history`（データベース記録の審級関係、
v1.1）、`allowed_citations`、そして下流モデルにバンドル内判決のみの引用と
根拠のない命題の unverified 表示を明示的に義務付ける
`verification_instructions` が含まれます。stderr には AI USE NOTICE も
出力されます。

v1.1 以降、`verification_instructions` には**見解レイヤーのセルフチェック**
（OPINION-LAYER SELF-CHECK）が追加されています。下流モデルは回答後に以下を
一つずつ確認しなければなりません：(a) ある判決に帰属させた判示がその判決の
抜粋に実際に存在すること（他の判決のものでも推論でもないこと）；(b) 裁判結果の
方向（勝訴／敗訴／破棄／棄却／差戻し）が逆転していないこと；(c) `case_history`
で破棄と表示された判決を現行有効な判示として引用していないこと。これは `check` の
バンドルレベル番号チェックを補完します — 事件番号が実在しても判示が実在するとは
限らず、見解レイヤーの照合は**全文を読んだモデル**にしかできません。これらの
ルールはその義務を各バンドルに書き込むものです。

`allowed_citations` は「引用可能な判決」のホワイトリストで、**理由全文を実際に
読み込んだ判決のみ**を含みます。CLI の `pack` は返された全判決を読み込むため、
両者は常に一致します。ホスト型 Remote MCP の `search_bundle`（`/v1/pack`）では
`read_top < max_results` の場合、上位 `read_top` 件のみ全文読み込みされ、残りは
閲覧用に `judgments` に残るものの `unread_candidates` に移されます（authority では
なく、裁判所の論理として引用不可）。詳細は
[`docs/mcp-anchor.md`](docs/mcp-anchor.ja.md)。

## 設定（任意）

デフォルトで公開エンドポイント `https://tlr.dr-lawbot.com` に接続し、キー不要で
使えます。サービス側から API キーを発行された場合は、環境変数または
`~/.twlegalrag/config.toml`（git-ignore 済み — **絶対に** commit しないこと）に
設定します：

```bash
export TWLEGALRAG_TLR_BASE_URL=https://tlr.dr-lawbot.com   # デフォルト
export TWLEGALRAG_TLR_API_KEY=...                          # 任意
```

```toml
[tlr]
# base_url = "https://tlr.dr-lawbot.com"
# api_key  = "..."
```

## プライバシーとデータの流れ

まず、**TLR サーバーを決して経由しないもの**：

- あなたと AI（Claude / ChatGPT / ローカルモデル）との**会話全文、アップロードした
  文書、AI が生成した回答**は、すべてあなたと AI プロバイダーの間で完結し、TLR を
  **一切経由しません**。TLR は retrieval-only のサーバーであり、受け取るのは
  あなたの AI クライアントが送信を決めた**検索クエリ文字列**と、その後の判決文書の
  取得リクエストだけです。
- **アカウント登録不要**：公開 REST エンドポイントはキーなしで使え、本サービスに
  ユーザーアカウントの仕組みはなく、クエリはいかなるアカウント身元にも
  紐付きません。
- 判決データ自体は台湾の**公開**裁判文書であり、レスポンスに非公開の個人情報は
  含まれません。

ネットワークを流れるものとして理解しておくべきこと：

- あなたの**検索語・質問**は判決取得のため TLR 検索エンドポイント
  （`https://tlr.dr-lawbot.com`）に送信されます。
- **TLR は検索品質分析のため、クエリ文字列・タイムスタンプ・IP 由来のメタデータ・
  結果件数を記録することがあります。個人の機密や秘匿すべき事実を送信しないで
  ください。クエリが生成モデルの学習に使われることはありません。**
- 本ツールは **LLM を呼び出さず、サーバー側トークンも使いません**。バンドルを
  自分で AI に渡す場合、その通信と費用は**あなたと選んだ AI プロバイダーの間**で
  発生し、本ツールとは無関係です。
- エンドポイントの API キー（ある場合）は環境変数に置き、設定ファイルを commit
  しないでください。

## 引用チェックの仕組み

`twlegalrag/faithful/` は**依存ゼロの純関数群**です（標準ライブラリの `re` +
`unicodedata` のみ）。回答テキストとバンドル内の判決抜粋を与えると
`pass` / `needs_review` / `fail` を返します。設計は保守的で、確信が持てない場合は
`fail` ではなく `needs_review` を返して誤検知を抑えます。**LLM を呼び出さず、
データベースにも触れない**、決定論的な文字列分析です。

⚠️ このディレクトリは内部コードの**スナップショット**であり、一部の関数
（`check_party_as_court` / `run_all_checks` など）は CLI では**使われていません**。
それらの存在は CLI が見解レイヤー／意味検証をできることを**意味しません** —
CLI が使うのはバンドルレベルの 2 チェックのみです。ファイル一覧を機能一覧と
読まないでください。詳細は `twlegalrag/faithful/VENDORED.md`。

## その他の接続方法（同一 TLR バックエンド）

この CLI は TLR 検索サービスを使う方法の一つです。同じバックエンド
`tlr.dr-lawbot.com` は、**Remote MCP** 経由で判決検索を AI ツールに直接組み込む
こともできます。いずれも同じ MCP エンドポイント
`https://tlr.dr-lawbot.com/mcp` を設定し、接続時に OAuth が自動完了します
（動的登録、API キーの申請・設定は不要）：

- **Claude（Remote MCP）**：Settings → Connectors → Add custom connector で
  URL に `https://tlr.dr-lawbot.com/mcp` を設定。
- **ChatGPT（MCP コネクタ）**：Connectors でカスタム MCP サーバーを追加し、
  URL に `https://tlr.dr-lawbot.com/mcp` を設定。
- **Claude Code（Skill、MCP ではなく CLI 経由）**：本リポジトリには
  [`skills/tw-legal-rag/`](skills/tw-legal-rag/) に既製の skill が同梱されて
  います。フォルダごとプロジェクトの `.claude/skills/` に置くだけです。本 CLI の
  `pack` サブコマンドをラップし、台湾の判決・法的論拠について質問すると Claude が
  自動検索し、バンドル内の `citation_id` のみ引用するよう義務付けます。同梱の
  `scripts/search_judgments.py` は実行ファイルを自動検出し、Windows の 2 つの
  落とし穴にも対応しています（skill 内の `SKILL.md` 参照）。

Remote MCP インターフェースには現在 4 つのツールがあります：`search_bundle`、
`search_judgments`、`get_judgment_fulltext`、そして 2026-08 追加の
`get_legal_reference`（行政解釈の文書番号による正確検索、
[`docs/mcp-anchor.md`](docs/mcp-anchor.ja.md) 参照）。最後のツールはまだ本 CLI には
組み込まれていません。

CLI・MCP・Claude Code skill のいずれを使っても、回答を生成するのは**あなた自身の
AI** です。本サービスが提供するのは判決コンテンツと検証可能な引用リンクのみです。

## アーキテクチャ

```
あなたの質問
   │
[検索]  TLR /v1/search   ──►  Layer-1 リスト + result_token
   │    TLR /v1/fulltext ──►  判決ごとの理由抜粋（上限あり）
   │
[パック] pack ──► bundle.json (citation_id / allowed_citations / 検証ルール)
   │             └─► 自分の AI ツールに渡す
   │
[検査]  check ──► バンドルレベル引用チェック（バンドル内外 + バンドル内引用文存在）
```

判決コーパス・embedding・検索ロジックはサーバー側にあり、**本リポジトリには
含まれません**。この CLI はオープンソースのクライアント兼引用チェックツールです。

## 免責事項

本ツールは分析補助であり、法的助言でも弁護士でもありません。引用された判決の
全文は必ず自分で読んでください。API 経由で取得する判決は台湾の公開裁判データで
あり、その利用についてはあなた自身が責任を負います。
